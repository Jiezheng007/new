# 性能与可用性自动化测试工具集

本目录 (`architecture_tests`) 包含了为本系统的软件架构大作业专门定制的**全自动化压测与容错探测脚本**。
如果您在未来修改了系统代码（例如优化了数据库查询、更换了数据库、重构了业务逻辑、或更换了更重的 Web 框架），您可以通过重新运行这里的测试脚本，来量化评估代码变更对系统性能和容错能力的影响。

## 目录结构说明

```text
architecture_tests/
├── scripts/
│   ├── run_multi_scenario_test.py      # 并发读写性能测试脚本
│   ├── run_ingestion_scale_test.py     # 大规模数据摄入吞吐量测试脚本
│   └── run_crash_recovery_test.py      # 容错性与进程崩溃恢复测试脚本
├── multi_scenario_performance_report.md # 自动生成的：并发与吞吐量性能测试报告
├── availability_report.md               # 撰写的：高可用性与系统容错分析报告
└── crash_recovery_report.md             # 自动生成的：宕机冷启动(MTTR)原始数据报告
```

---

## 🚀 如何重新进行测试 (一键执行指南)

所有的测试脚本都采用了**“一键化”设计**（自动拉起后端服务 -> 自动压测探测 -> 自动生成并覆写报告 -> 自动清理后台进程），因此执行起来非常简单。

> **⚠️ 前置要求 (重要)**
> 在运行以下任何测试之前，请**务必确保您已经关闭了手动启动的后端开发服务器**（例如您自己运行的 `uvicorn app.main:app`）。测试脚本会在后台自动占用 `8000` / `8001` 端口，如果原端口已被占用，会导致测试脚本运行失败。

请在项目根目录（即 `backend/` 和 `architecture_tests/` 的同级目录）打开终端，根据需要执行以下命令：

### 1. 基础性能并发测试 (并发读/写混合场景)

**适用场景**：当您优化了普通 API 接口（如查询总览数据、执行规则引擎）的响应速度，或者调整了数据库连接池配置后。

```bash
python architecture_tests/scripts/run_multi_scenario_test.py
```
* **耗时**：约 2 分钟。
* **执行逻辑**：脚本会自动对“状态总览模块”和“规则引擎模块”发起从轻量到中等规模的多线程并发攻击。
* **结果去向**：执行完毕后，生成的吞吐量（RPS）和平均响应时间（RT）会自动更新在 `multi_scenario_performance_report.md` 中的对应部分。

### 2. 大规模数据摄入吞吐量测试 (数据抓取写入模块)

**适用场景**：当您优化了数据库的单文件锁瓶颈，或者采用了批量插入（Bulk Insert）、消息队列异步落库等技术后。

```bash
python architecture_tests/scripts/run_ingestion_scale_test.py
```
* **耗时**：约 1 分钟。
* **执行逻辑**：自动构造包含 100条、1000条、5000条、10000条数据的超大 JSON 载荷，直接轰炸数据摄入接口，测试系统“吞下并落盘数据”的绝对吞吐速度。
* **结果去向**：结果同样会自动更新在 `multi_scenario_performance_report.md` 中的「大规模摄入测试」专属报告区。

### 3. 容错性与崩溃恢复测试 (可用性与 MTTR)

**适用场景**：当您更换了 Web 框架（想对比冷启动时间）、或者修改了鉴权逻辑与会话管理策略（想验证宕机是否会导致用户登出或丢数据）时。

```bash
python architecture_tests/scripts/run_crash_recovery_test.py
```
* **耗时**：约 15 秒。
* **执行逻辑**：脚本会让系统平稳运行，随后使用操作系统的终极命令 `taskkill /F /T` 在底层直接击杀进程，随后模拟运维介入拉起服务。通过高频探针，精确计算出系统的总瘫痪时间与**框架冷启动复原耗时 (MTTR)**。
* **结果去向**：每次运行产生的精确毫秒级时间戳战报会自动覆盖写入到 `crash_recovery_report.md` 中。
